# Claude Code 增补任务：多端响应式适配规格（手机 / 平板 / 桌面）

## 这份文档的定位

本文档是 `CLAUDE_CODE_V0.2_LEVELS_GAMIFIED.md`（游戏化闯关升级）的**增补规格**。两份配合使用：主提示词负责功能与趣味性，本文档负责让这套网页在**手机、平板、桌面**三类设备上都显示和操作良好。

⚠️ **重要认知**：这是**同一套静态网页**的响应式适配，不是做三个不同的 app。所有适配通过 CSS 媒体查询 + 弹性布局实现，一套代码自动适应不同屏幕。最终产物仍是部署到 GitHub Pages 的同一个项目。

执行方式：可以把本文档接在主提示词后面一起给 Claude Code，或在主功能做完后单独执行本文档做适配打磨。

---

## 一、三类设备的断点与场景

用以下统一断点（写进 CSS，全项目一致）：

| 设备 | 屏宽断点 | 典型设备 | 使用场景 |
|---|---|---|---|
| 📱 手机 | ≤ 640px | iPhone、安卓手机 | 竖屏单手，碎片时间，拇指操作 |
| 📲 平板竖屏 | 641px – 1024px | iPad 竖屏 | 孩子学习主力设备，沉浸使用 |
| 💻 平板横屏 / 桌面 | > 1024px | iPad 横屏、电脑 | 横屏学习、家长辅导 |

**核心适配原则**：
- 手机：单列、大按钮、纵向流、底部导航拇指可达
- 平板：善用更大画布，双列/更大元素/更丰富的地图，但内容不要无限拉伸
- 桌面：内容居中限宽（最大 1100px 左右），两侧留白，避免元素拉得过宽难看

## 二、全局响应式基础（先做这些）

### 1. viewport 与缩放
确认 `index.html` 的 viewport 正确（应已有）：
```html
<meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover">
```
- 加 `viewport-fit=cover` 适配 iPhone 刘海屏/全面屏
- 不要禁用用户缩放（去掉 `maximum-scale=1, user-scalable=no` 如果有），无障碍需要

### 2. 安全区域（刘海屏/全面屏）
顶部导航和底部导航栏要避开手机的刘海和小白条，用 CSS env：
```css
.top-nav { padding-top: env(safe-area-inset-top); }
.bottom-nav {
  padding-bottom: env(safe-area-inset-bottom);
}
```

### 3. 主内容容器限宽
所有页面的主内容容器统一：
```css
.app-container {
  width: 100%;
  max-width: 1100px;   /* 桌面下不无限拉宽 */
  margin: 0 auto;
  padding: 0 16px;
}
```
平板和桌面下内容居中，两侧自然留白。

### 4. 触控目标尺寸
所有可点击元素（按钮、关卡节点、选项、导航）**最小 44×44px**（苹果人机指南标准），手机上尤其重要，避免孩子点不准。

### 5. 字号响应式
用 `clamp()` 让关键文字在不同屏幕自动缩放，例如标题：
```css
.title { font-size: clamp(20px, 4vw, 32px); }
```
正文最小不低于 14px（孩子要看清）。

### 6. 横竖屏切换
监听 `orientationchange` / `resize`，对 Canvas 游戏和关卡地图重新计算布局，避免旋转后错位。

## 三、★ 关卡地图的多端适配（重点）

关卡地图是最需要精细适配的部分，三种屏幕差异极大。

### 📱 手机（≤640px）
- **单列纵向蜿蜒路径**：关卡节点左右小幅 zigzag（偏移约 ±25% 屏宽），路径在中间蜿蜒
- 节点直径 52-56px
- 一屏显示约 4-5 个关卡，纵向滚动
- 装饰 emoji 适量（太多挤），尺寸小
- 进入自动滚到当前关

### 📲 平板竖屏（641-1024px）
- 仍是纵向滚动，但**路径振幅加大**（左右偏移更夸张，蜿蜒感更强，利用更宽的屏）
- 节点直径放大到 64-72px，星星、图标更清晰
- 一屏显示 5-6 关
- 装饰元素增多、变大，场景更丰富（这是孩子主力设备，值得做精致）
- 大区主题切换的视觉分隔更明显（如区与区之间加一个主题横幅）

### 💻 平板横屏 / 桌面（>1024px）
- 横屏屏幕很宽，**不要让路径只占中间一条细线**。两种方案择优：
  - **方案 A（推荐）**：路径做成横向或更大幅度的 S 形蜿蜒，利用横向空间，节点分布更舒展
  - **方案 B**：地图区域限宽居中（如 700px），两侧放装饰插画/侧边栏（显示当前宠物、本区进度、收集图鉴入口），不浪费空间
- 节点可以更大，hover 时有放大/提示效果（桌面有鼠标）
- 整体居中，最大宽度约 1000-1100px

### 通用
- SVG 路径的控制点根据**实际容器宽度动态计算**，不要写死像素，用百分比或基于 viewBox
- 窗口 resize / 旋转时重新生成路径和节点坐标

## 四、★ 关卡内游戏的多端适配（重点）

关内玩法（选择题、拼字母、听音、快速反应、Boss 战）的适配：

### 通用 HUD
- 生命值/连击/倍率的 HUD 在手机上紧凑横排，平板/桌面可更大更醒目
- HUD 固定顶部，不随内容滚动

### 选择题类玩法
- 手机：选项**单列纵向排列**，每个选项占满宽度，够大好点
- 平板/桌面：选项可 **2×2 网格**，利用横向空间，但单个选项仍要够大
- 选项按钮高度手机 ≥52px，平板 ≥60px

### 字母拼拼乐
- 字母块尺寸响应式：手机 44-48px，平板 56-64px
- 字母块自动换行（flex-wrap），不同屏幕每行数量自适应
- 答案区和字母池在小屏上下排列，大屏可左右排列

### Boss 战 / Canvas 游戏
- Canvas 尺寸用 `clientWidth` 动态设定，不要写死
- 注意 **devicePixelRatio**：高清屏（iPad/手机 Retina）要按 dpr 放大 canvas 实际像素再缩放，否则画面糊
  ```javascript
  const dpr = window.devicePixelRatio || 1;
  canvas.width = cssWidth * dpr;
  canvas.height = cssHeight * dpr;
  ctx.scale(dpr, dpr);
  ```
- 触控和鼠标都要支持（手机/平板触控，桌面点击）：用 pointer events 或同时绑 touch + click

### 即时反馈动画
- 金币飞行、连击弹跳、暴击特效在不同屏幕都要正常（用相对定位/transform，不写死坐标）
- 全屏彩带等特效适配屏幕尺寸

## 五、★ 背诵与阅读模块的多端适配

### 文章阅读
- 手机：单列，正文字号 16px 起，行高松一点（1.8）方便孩子读
- 平板/桌面：正文区限宽（如 680px）居中，避免一行太长（一行最佳 40-75 字符），太长伤阅读

### 背诵挖空
- 挖空后的下划线/空格在各屏幕都要清晰可点
- 逐词高亮（对/漏/错三色）在小屏上也要分得清

### 录音按钮
- 录音是核心交互，按钮要**大而醒目**，手机上尤其，方便孩子点
- 录音中的状态（波纹/动画）适配各屏幕

## 六、导航与通用组件适配

### 底部导航（手机）/ 侧边或顶部（桌面可选）
- 手机：底部 Tab 导航，拇指可达，每个 Tab ≥44px，避开安全区
- 平板竖屏：底部导航仍适用
- 桌面/平板横屏：可保持底部，或考虑顶部导航（择一即可，不强制改）

### 弹窗 modal
- 手机：modal 接近全屏或底部弹出（bottom sheet 风格），留出关闭区
- 平板/桌面：modal 居中，限宽（如 480px），周围暗色遮罩

### 卡片网格
- 单词大冒险首页、勋章墙等网格：手机 2 列、平板 3 列、桌面 4 列，用 Tailwind 响应式类（`grid-cols-2 md:grid-cols-3 lg:grid-cols-4`）

## 八、实现建议

1. **优先用 Tailwind 响应式前缀**（`sm: md: lg:`）实现大部分适配，少写自定义媒体查询
2. **弹性布局优先**（flex / grid + 百分比 / clamp），少写死像素
3. **关卡地图和 Canvas 的坐标基于容器实际尺寸动态算**，监听 resize 重算
4. **不要为不同设备写完全不同的 DOM**，用同一套结构 + CSS 控制呈现，便于维护
5. 改完不要破坏已做好的功能和视觉，只调整布局适配
